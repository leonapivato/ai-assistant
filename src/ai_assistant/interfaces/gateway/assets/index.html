            Notifications I am holding

            What may reach you unprompted

            Out of the box nothing interrupts: every class is held for when you next look. Only classes you have set appear below; anything else takes the default. Each control here is its own act — what it does not name is read and written back untouched, and if something else changes these at the same moment, the last write wins.

            Accounts I am connected to

            Everything connected right now. This list is never shortened: it arrives whole or not at all. A reference is minted by the hub — you cannot type one, which is why connecting an account a second time can never overwrite the first.

            What was done to connections

            One row per act, newest first, in the order the store recorded them. There are no times here and the order is not one. No row says what is connected now — the panel above is the only answer to that.

            Every session ends when the gateway process does. A session is held in that process's memory and written down nowhere, so a gateway that starts again has no memory of this one.

            A session also ends on its own: at gateway_session_ttl from when it started, and after gateway_session_idle_timeout with no request the gateway admitted. Watching for notifications is not such a request, so a page left open and asked nothing expires on time.

            Closing the browser may end it and may not — that depends on a setting of your browser's that the gateway cannot see. Either way the way back is a fresh bootstrap value, minted at the machine the gateway runs on.

            This page stays signed in for as long as your sign-in lasts. When your sign-in ends, you sign in again at the sign-in page, and nothing else here asks you for anything.
